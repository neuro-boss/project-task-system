# Журнал работы, отчёты и паспорта

Нужен настроенный общий Hub из [yougile-hub.md](yougile-hub.md). Его CLI и home
указаны в локальном `project-task-hub.json` внутри CODEX_HOME (по умолчанию ~/.codex).
Все следующие команды выполняются из папки **сервиса**, не каталога навыка.

## Отчёты по запросу

```bash
node cli.mjs report --period day --project all
node cli.mjs report --period week --project /path/to/project
node cli.mjs report --period month --date 2026-09-15 --project all
node cli.mjs report --from 2026-10-01 --to 2026-10-15 --project all
```

Периоды: один локальный день, неделя понедельник–воскресенье, календарный месяц.
`--date` выбирает день или содержащую его неделю/месяц; без него используется сегодня.
`--from/--to` — произвольный включительный диапазон. Для «последних семи дней»
рассчитайте точные границы и передайте их явно. Часовой пояс — системный, либо
`reportTimeZone` в settings.json, либо явный `--timezone Europe/Moscow`.

Без --project отчёт охватывает все зарегистрированные проекты. Выключенный YouGile
не исключает локальный проект из отчёта. Ненайденные/недоступные источники и
завершённые задачи без подтверждённых дат показываются как пробелы покрытия.
Не обещайте отчёт обо всех чатах Codex: он содержит только зафиксированную работу.

Результат: Markdown, JSON и самодостаточный HTML в `<hub>/.local/reports`.
HTML содержит выбор проекта, даты, быстрые day/week/month, поиск, результаты,
подтверждения и отдельно текущие задачи In Progress. Дата сбора видна в отчёте.
Открывайте файл как локальный документ; сервер/публикация для просмотра не нужны.
Часовой tick обновляет latest/index без накопления часовых архивов, а явный report
сохраняет отдельный снимок. Старый открытый файл сам не превращается в новый отчёт:
обновите просмотр latest после фонового цикла или сформируйте отчёт заново.

## Что попадает в журнал

- Исторические результаты из WORK_LOG и Completed сохраняют исходную дату.
  Первичная индексация текущих задач не считается работой в день установки.
- Запись Done, её Work Log и Completed объединяются по проекту/задаче/дате.
  Расхождение дат отмечается явно; для результата принимается дата WORK_LOG.
- Новые изменения статуса/содержания датируются **обнаружением**, с границей
  предыдущей проверки. Это не точный поминутный трекер работы агента.
- Исследования, решения, проверки, блокеры и выпуск без перехода задачи записываются
  отдельно. Оценка Estimate не используется как фактически потраченное время.

```bash
node cli.mjs collect --project all
node cli.mjs collect --project all --apply
node cli.mjs log --project /path/to/project --kind research --task TASK-001 --summary "Подтверждённый результат исследования" --apply
node cli.mjs log --project /path/to/project --file /path/to/local-note.json --apply
```

Без --apply collect/log только показывают план. report по смыслу создаёт локальные
файлы и обновляет индекс, но не обращается в YouGile. Поддерживаются kind:
progress, research, decision, blocker, release, check. JSON заметки:

```json
{"kind":"decision","taskId":"TASK-001","summary":"Принятое решение","outcome":"Чем подтверждено","id":"stable-optional-id"}
```

Повтор с тем же id не создаёт вторую заметку; без id совпадающие заметки одной
задачи/типа/дня объединяются. Не дублируйте завершение задачи отдельной заметкой:
используйте Done/WORK_LOG. Не сохраняйте секреты, персональные данные и приватные
ссылки в журнал. Автоматическая очистка распространённых шаблонов ключей, email и
URL — дополнительная мера; она не заменяет проверку текста агентом.

Журнал — `<hub>/.local/activity-<projectId>.json`, отдельная атомарно обновляемая
запись на проект под блокировкой. Задачи не переписываются. Ошибка API не отменяет
локальные результаты. История вне WORK_LOG/Completed автоматически не выдумывается.

В подключённом **проекте** те же действия доступны через локальный мост:

```bash
node tools/taskplanner-yougile-hub.mjs log --kind research --summary "Подтверждённый итог" --apply
node tools/taskplanner-yougile-hub.mjs report --period week
```

Мост задаёт свой проект из реального пути и не меняет назначение YouGile.

## Оформление описаний

Hub преобразует исходный Markdown в ограниченный безопасный HTML. Поддерживаются
выделения, абзацы/переносы, заголовки, списки/чек-листы, код, таблицы, HTTP(S)/mailto
ссылки. Raw HTML остаётся буквальным текстом; javascript-ссылки не исполняются.
YouGile может нормализовать `<br>` в `<br />`; это не повод повторять PUT.
Карточки обновляются с прежними ID и сохраняют назначения, посторонние стикеры и
связи Ганта. Большое первоначальное обновление идёт ограниченными пакетами.
Это поведение общего Hub; самостоятельный коннектор остаётся отдельным режимом.

## Паспорт проекта: автоматическое создание и обновление

Начиная с Hub 0.5, при `passports.enabled=true` создаёт docs/project-passport.md после
подключения нового проекта, сохраняя существующий файл. Черновик требует заполнения
подтверждёнными фактами. Изменения паспорта, README и docs/product.md,
architecture.md, integrations.md, deployment.md, decisions.md попадают в очередь.
Текущие задачи и WORK_LOG не вызывают обновления паспорта. Удаление документа
тоже считается изменением. Проверка выполняется при onboarding/синхронизации
и часовым tick; без изменений нет публикации.

```bash
node cli.mjs passport --pending
node cli.mjs passport --project /path/to/project --refresh
node cli.mjs passport --project /path/to/project --refresh --apply
node cli.mjs passport --project /path/to/project
```

--refresh без apply показывает план. С apply создаёт черновик при отсутствии,
очередь и HTML-фрагмент. Последняя команда без флагов сохраняет прежний HTML-экспорт;
knowledgeBasePublished=false относится только к экспорту, а не к наличию страницы.

Начиная с Hub 0.5, публикация страниц выполняется через официальный MCP YouGile:
kb_list_pages, kb_get_page, kb_write_page; get_project_tree и create_board нужны
для поиска и создания нативной базы знаний. Подключите MCP в Codex через OAuth
с чтением и изменением. Не копируйте токены. На момент проверки MCP требует
открытую авторизованную вкладку YouGile.

Локальная opt-in политика: passports.publisherEnabled=true, publisher="mcp" и
passports.mcp с server="yougile", binary (актуальный бинарник Codex с app-server),
teamUrl (проверенный URL вашей команды YouGile). Персональные значения не входят
в навык. Установка навыка сама по себе не разрешает публикацию.

```bash
node cli.mjs passport --project /path/to/project --mcp-read --out /local/inspection.json
node cli.mjs passport --project /path/to/project --mcp-publish /local/review.json
node cli.mjs passport --project /path/to/project --mcp-publish /local/review.json --apply
```

Агент объединяет локальные факты и ручной текст страницы в review JSON:
revision, remoteFingerprint (из чтения), content (Markdown), contentMode=replace.
Для чистого дополнения доступны append/prepend. При совпадении текста команда
подтверждает чтение без записи. Сохраняются прежние URL, UUID, база знаний,
название страницы и ручные дополнения. Без привязки сначала выполняется поиск;
при отсутствии создаётся страница или нативная knowledgeBase. Пропавшая привязанная
страница и неоднозначные результаты не заменяются новой страницей.

Перед записью проверяются локальная revision и удалённый fingerprint, сохраняется
резервная копия. После записи полный Markdown читается повторно; только успешная
сверка обновляет baseline и очищает очередь. Неизвестный результат создания не
повторяется вслепую. Атомарного compare-and-swap в YouGile нет: при замеченном
конфликте обе версии сохраняются для разбора. Протокол —
[ PASSPORT-WORKER.md ](../assets/project-task-hub/PASSPORT-WORKER.md).

Правила агента вызывают обработчик после важных изменений. В Hub 0.6 часовой
Windows tick сам проверяет очередь без модели и вызывает `codex queue` только
при наличии разрешённых pending-паспортов. Пустая очередь не запускает Codex.
Для этого локально задайте passports.wake: enabled=true, binary (бинарник Codex
с queue), threadId (UUID выбранного существующего чата). Установка навыка сама
по себе не выбирает чужой чат и не разрешает отправку сообщений.

```bash
node cli.mjs passport --wake
node cli.mjs passport --wake --apply
```

Preview только читает локальные данные; apply отправляет один запрос существующему
чату. Очередь ожидания объединяет новые изменения и не дублирует пробуждения.
Сохранённый ID запроса передаётся в --wake-start/--wake-finish: агент подтверждает
начало и завершение, включая ошибки MCP. Начатая работа имеет lease два часа для
восстановления после прерывания. После неизвестного результата отправки сначала
проверь wake.json и очередь чата; не удаляй receipt ради слепого повтора.

При переводе существующей установки сохрани часовой Windows-планировщик и через
native automation_update поставь прежний безусловный heartbeat в PAUSED, сохранив
его prompt, период и настройки уведомлений. Не заменяй его другим частым запуском
модели. Очередь, обновление задач и отчётов остаются в скрипте; агент выполняет
смысловое объединение и MCP-публикацию при наличии работы. При недоступности MCP
pending сохраняется до следующего часового запроса после завершения текущего.
В фоне сообщай только о существенном обновлении, новой ошибке или нужном решении;
повторяющуюся ошибку не анонсируй каждый час. Браузерный редактор не нужен.

В паспорт включаются назначение, проверенные публичные ссылки, вход в админку,
окружения, интеграции и эксплуатация. У фактов — источник/дата; неизвестные адреса
помечаются явно. Не копируйте секреты, персональные данные и приватные адреса.
Возможности редактора описаны в [справке YouGile](https://help.yougile.com/books/baza-znanii-yougile/page/baza-znanii).


В проектах без YouGile установщик общего Hub добавляет отдельный локальный помощник
`tools/project-task-hub.mjs` и блок PROJECT-ACTIVITY. Он поддерживает те же команды
log/report/collect/passport, не создавая YouGile-проектов. Установщик сохраняет
пользовательские правила и исключает свой указатель из Git. Для существующего Hub
правила можно установить явно: `python install-activity.py --project <путь>`
(preview), затем та же команда с --apply. Конфликтующий помощник не перезаписывается.
