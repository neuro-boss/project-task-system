# Как работает связка TaskPlanner, API и MCP YouGile

В Hub 0.6.0 задачи синхронизируются программно через REST API YouGile.
Паспорта публикуются в базе знаний через официальный MCP. Раз в час обычный
скрипт проверяет изменения; отдельный запуск Codex нужен при непустой очереди
паспортов. Все три части выполняют разные обязанности.

## Задачи: локальные файлы → API → карточки

1. Агент добавляет или изменяет задачу в `.tasks/*.md`.
2. По управляемым правилам проекта агент запускает синхронизацию. Это команда
   агента, а не системное наблюдение за каждым сохранением файла.
3. Коннектор читает локальную задачу, карту связей и настройки проекта.
4. REST API создаёт карточку или обновляет прежнюю: статус, описание, приоритет,
   выбранные стикеры, оценки и даты. Описание преобразуется из Markdown в HTML.
5. Локальная карта сохраняет соответствие ID. Повтор не создаёт дубль; чужие
   назначения, посторонние поля и существующие связи сохраняются по правилам Hub.

Для этих операций модель не требуется. Прогнозы рассчитываются кодом из оценок
и рабочего календаря; они не выдаются за обещанные сроки. Старые Done/Rejected
не импортируются массово без отдельного запроса.

Управляемые задачи меняйте в `.tasks`, затем запускайте коннектор. Изменение тех
же управляемых полей напрямую через MCP не обновляет локальный источник; при
последующей синхронизации они могут снова принять локальные значения.

## Проекты: первичное подключение и часовая подстраховка

При bootstrap в заранее разрешённой папке hook использует общую локальную политику.
Существующий YouGile-проект принимается с прежними ID, досками и картами; при
отсутствии подключения создаётся проект с доской и колонками через API.

Раз в час `node cli.mjs tick --apply`:

- обнаруживает пропущенные проекты с `.tasks` в разрешённых папках;
- повторяет незавершённое подключение и синхронизацию задач;
- собирает локальный журнал и обновляет последний обзор;
- сравнивает документы и проверяет очередь паспортов.

Скрипт не запускает модель для этих проверок. Вручную отключённые проекты и
исключения сохраняются. Пустая папка без `.tasks` не становится проектом фоном.

## Паспорта: документы → очередь → Codex → MCP

При подключении создаётся только отсутствующий `docs/project-passport.md`.
Имеющийся документ сохраняется. Изменения паспорта, README и документов продукта,
архитектуры, интеграций, развёртывания и решений попадают в очередь по хешам.
Изменение задачи или WORK_LOG само по себе не требует переписывать паспорт.

При разрешённой локальной политике и непустой очереди скрипт вызывает
`codex queue --thread <UUID существующего чата> --message <инструкция>`.
В ожидании обработки новые изменения объединяются: второй запрос не отправляется.
При пустой очереди команда Codex не вызывается.

Агент обрабатывает запрос по [PASSPORT-WORKER.md](../assets/project-task-hub/PASSPORT-WORKER.md):

1. Подтверждает начало по ID запроса и перечитывает актуальную очередь.
2. Проверяет изменённые факты по документам проекта. Секреты в паспорт не переносит.
3. Через MCP находит и читает текущую страницу базы знаний в полном Markdown.
4. Сравнивает её с предыдущей проверенной версией и локальным паспортом, объединяет
   новые сведения с ручными дополнениями. При неоднозначном конфликте сохраняет
   обе версии для разбора.
5. Проверяет план публикации. Перед записью обработчик повторно сверяет локальную
   revision и удалённый fingerprint, сохраняет резервную копию.
6. Через MCP обновляет тот же UUID страницы, сохраняя её URL, название и базу.
   После записи повторно читает Markdown и сверяет результат. Только успешная
   проверка подтверждает обработанную версию документа.
7. Подтверждает завершение запроса, включая случай ошибки. Оставшаяся работа
   может повториться при следующем часовом запуске скрипта.

Для новой страницы сначала выполняется поиск существующего паспорта. Если базы
нет, создаётся нативная `knowledgeBase` без колонок задач, затем страница.
Исчезнувшая привязанная страница не заменяется новым объектом. Неизвестный исход
создания или отправки запроса нельзя повторять вслепую: сначала проверяются
удалённые объекты, очередь чата и локальные подтверждения.

MCP-методы этого обработчика: `get_project_tree`, `create_board`, `kb_list_pages`,
`kb_get_page`, `kb_write_page`. Страницы принимают Markdown; описание обычной
карточки в нашем API-коннекторе передаётся как HTML. Это разные объекты и форматы.

## Что нужно настроить один раз

Для задач нужны разрешённые папки проектов, профиль вашей компании и защищённый
локальный файл API-ключа. Для паспортов отдельно подключается официальный MCP
YouGile в Codex через OAuth с чтением и изменением. Адрес сервера берётся из
раздела «ИИ-ассистенты (MCP)» вашего профиля YouGile.

После проверки разрешений добавьте в локальный `<hub>/.local/settings.json`
политику паспортов, сохраняя остальные настройки. Значения ниже — примеры путей
и мест для заполнения, их нельзя копировать как готовое подключение:

```json
{
  "passports": {
    "enabled": true,
    "publisherEnabled": true,
    "publisher": "mcp",
    "mcp": {
      "server": "yougile",
      "binary": "/absolute/path/to/codex",
      "teamUrl": "https://ru.yougile.com/team/<ваша-команда>"
    },
    "wake": {
      "enabled": true,
      "binary": "/absolute/path/to/codex",
      "threadId": "<UUID выбранного существующего чата>"
    }
  }
}
```

`server` — имя настроенного MCP в Codex; `binary` — актуальный исполняемый файл
Codex с командами `app-server` и `queue`. На Windows укажите полный путь к
`codex.exe`. `teamUrl` берётся из наблюдаемого адреса вашей команды, `threadId` —
из явно выбранного существующего чата. Личные значения не входят в навык.

Установка навыка сама по себе не включает эту политику. Публикация и отправка
запросов выбранному чату должны входить в разрешённый пользователем сценарий.
Если прежде был безусловный часовой heartbeat, при переходе приостановите его
через штатный инструмент automations, сохранив настройки. Достаточно одного
часового скрипта; новый периодический запуск модели создавать не нужно.

Проверка из установленного Hub:

```bash
node cli.mjs passport --pending
node cli.mjs passport --wake
node cli.mjs passport --wake --apply
```

Вторая команда показывает план без отправки сообщения, третья отправляет его
только при наличии работы. Часовой `tick --apply` вызывает эту проверку сам.
MCP-транспорт не извлекает OAuth-токены: авторизацию обслуживает Codex.

## Как выбирать инструмент

| Работа | Инструмент в этой системе |
| --- | --- |
| Повторяемая синхронизация карточек и массовые изменения по правилам | API и код |
| Поиск проектов и проверка очереди по расписанию | Скрипт без модели |
| Объединение фактов и ручного текста паспорта | Codex и MCP |
| По запросу понять обсуждение или историю задачи в YouGile | Доступные MCP-инструменты и агент |
| Отчёт за день, неделю или месяц по нашим проектам | Локальный журнал и код отчётов |

MCP — интерфейс вызова инструментов, он сам по себе не требует рассуждения модели
на каждый запрос. В нашей схеме агент используется для содержательной работы
с паспортом. API-коннектору задач и пустой часовой проверке агент не нужен.

## Ограничения и ошибки

Для часового скрипта нужен включённый компьютер и доступные проекты. Для работы
агента и текущего MCP YouGile нужны доступный Codex, действующая авторизация и
открытая авторизованная вкладка YouGile. API-синхронизация задач не зависит от неё.

Если MCP недоступен или есть конфликт, локальные задачи и очередь сохраняются.
Начатый запрос получает lease на два часа для восстановления после прерывания.
Ожидающий запрос не дублируется; неизвестный исход отправки требует проверки.
YouGile не предоставляет атомарное условное обновление страницы: повторная сверка
уменьшает риск гонки, но одновременное ручное редактирование лучше завершить
до публикации агентом.

Отчёт строится по журналу проектов, а не по всем чатам Codex. Неизвестные даты
завершения и непроверенные ссылки не выдумываются. Подробности настройки —
[общий Hub](yougile-hub.md), [журнал и отчёты](activity-reports.md).
