# Подключение YouGile к TaskPlanner

Это необязательная локальная односторонняя синхронизация для проекта с пятью стандартными состояниями TaskPlanner. Главный источник — `.tasks/*.md`; чужие задачи, компания, доска, ключ и ID не используются. Нужны Python 3 и Node.js 20+; npm-зависимости не устанавливаются.

## 1. Установите систему задач

Установите навык из `https://github.com/neuro-boss/project-task-system` через Codex `$skill-installer` и создайте доску в своём проекте с помощью `$project-task-system`. Плагин TaskPlanner полезен, но необязателен: доска состоит из Markdown-файлов. Подробности — в [инструкции по установке](installation.md). Существующая доска сохраняется; перед работой изучите её `.tasks/config.json`, `AGENTS.md` и незавершённые изменения.

## 2. Установите коннектор отдельным шагом

В клоне или установленной копии **этого** репозитория выполните команды, заменив путь на абсолютный путь к целевому проекту:

```bash
python scripts/bootstrap_yougile.py --target /absolute/path/to/project
python scripts/bootstrap_yougile.py --target /absolute/path/to/project --apply
python scripts/bootstrap_yougile.py --target /absolute/path/to/project --check
```

Первая команда только показывает план, без сети и записи. Установщик добавляет четыре JS-файла в `tools/`, безопасный `.tasks/yougile.example.json`, правила исключения Git и блок `YOUGILE-SYNC` в существующие файлы правил агента. Ключ он не читает, в YouGile не обращается. Отличающиеся существующие скрипты и конфигурация сохраняются: разберите конфликт вручную, не перезаписывая их. Повторный `--apply` не должен ничего менять. В Git можно добавлять только публичные файлы, а не локальную конфигурацию и карту ID.

## 3. Настройте свою компанию и доску

Создайте или выберите проект и доску в **своей** компании YouGile. Рекомендуемый порядок колонок слева направо: `Бэклог` → `Следующие` → `В работе` → `Готово` → `Отклонено`. В локальном JSON сопоставьте их состояниям `Backlog`, `Next`, `In Progress`, `Done`, `Rejected`. Если API в вашем аккаунте добавляет новые колонки слева, создайте их в обратном порядке и проверьте фактический вид доски. Необязательные коды цветов колонок для повторения образца: `1, 3, 4, 6, 7`; цвет карточек по приоритету задаётся отдельно.

Скопируйте `.tasks/yougile.example.json` в `.tasks/yougile.local.json`. Заполните уникальный стабильный `workspaceKey`, `projectId`, `boardId` и все пять ID в `columns`. Настройте часовой пояс, рабочий день, оценки и активные состояния. Не вставляйте секреты ни в один JSON. Локальный файл исключён из Git. Если используете существующие объекты YouGile, проверьте, что все ID относятся к выбранной доске.

Попросите уполномоченного администратора своей компании получить API-ключ YouGile v2. Храните его в исключённом из Git `.tasks/yougile.api-key.txt` или, лучше, в одном защищённом файле **вне всех репозиториев**, указав абсолютный путь в `apiKeyFile` каждого проекта. Один ключ может обслуживать несколько проектов **той же компании**, если у учётной записи есть доступ. Альтернатива — `YOUGILE_API_KEY`. Не передавайте ключ ИИ в чате, в аргументах команд, Git или логах; не выводите Authorization header. Замена общего ключа затронет все подключённые проекты. Перед публикацией убедитесь, что локальная конфигурация, ключ, карта и хеши не отслеживаются Git.

## 4. Проверьте и запустите пилот

Из каталога **целевого** проекта:

```bash
node tools/taskplanner-yougile-sync.mjs
node tools/taskplanner-yougile-sync.mjs --discover
node tools/taskplanner-yougile-sync.mjs --doctor
node tools/taskplanner-yougile-sync.mjs --apply --task TASK-001
node tools/taskplanner-yougile-sync.mjs --apply --task TASK-001
```

Первая команда выполняет локальный dry-run без ключа и сети. `--discover` читает доступные ID объектов через API, `--doctor` проверяет выбранную доску и колонки. Замените `TASK-001` на ID своей задачи. Посмотрите созданную карточку, повторите пилот и убедитесь, что сохранён тот же ID YouGile. Карта ID и хеши данных сохраняются в исключённых из Git файлах. Неизменённая карточка при повторе пропускается; новый дневной прогноз Ганта или изменение задачи могут вызвать обоснованное обновление. При сетевой ошибке не создавайте вторую карточку вручную — сохраните карту и повторите команду. Создание использует стабильный `idempotencyKey` вида `workspaceKey:taskId`.

Явный `--task <ID>` позволяет отправить и только что завершённую задачу, которой ещё нет на доске. Для старой задачи с отсутствующими датами применяйте `--import-history --task <ID>` только после проверки dry-run: этот режим восстанавливает подтверждаемые даты из Git и `WORK_LOG.md`.

После пилота `node tools/taskplanner-yougile-sync.mjs --apply` синхронизирует настроенные активные состояния и уже сопоставленные карточки. По умолчанию между API-запросами не менее 1250 мс. Старые задачи `Done` массово **не** импортируются. Исторический импорт — отдельное согласованное действие с предварительным dry-run `--import-history`; отсутствующие даты не выдумываются.

## 5. Необязательные продуктовые модули

Сначала изучите реальные задачи и согласуйте взаимоисключающие модули. Пример для локального JSON: `"modules": [{"key":"frontend","name":"Frontend","tags":["web"],"keywords":["интерфейс"]},{"key":"other","name":"Другое"}]`, `"moduleFallback": "other"`, `"moduleStickerName": "Модуль"`. Приоритет правил соответствует порядку массива; `moduleOverrides` задаёт исключения по ID задачи. Dry-run отмечает неоднозначные совпадения. После согласования создайте на доске один строковый стикер с состояниями, названными точно как модули, и проверьте его на пилотной карточке. Если модули не нужны, оставьте `modules: []` и `moduleStickerName: null`.

## 6. Даты, мониторинг и границы

`Created`, `Started`, `Completed` и необязательный назначенный человеком `Due` сохраняются в тексте задачи TaskPlanner и описании карточки YouGile. Коннектор **не** меняет серверную дату создания карточки YouGile. Для `Next` и `In Progress` расчёт по оценке и рабочему календарю показывается в Ганте как **прогноз**, а не обещанный срок. `Backlog` не получает автоматических плановых дат. У завершённой задачи с подтверждёнными датами интервал Ганта — `Started` (или `Created` как запасной вариант) → `Completed`.

Установленное правило агента запускает точечную синхронизацию после изменения локальной задачи, когда коннектор настроен. Это действие агента, **не** постоянно работающий демон или системный планировщик. Периодический запуск `--apply` через собственный планировщик настраивайте отдельно, только после пилота, с защищённым ключом и безопасными логами. Первичные инструменты проверки — dry-run и `--doctor`. Карточки клиентов, созданные прямо в YouGile, автоматически не импортируются; обратному потоку нужны отдельные правила прав, владельца данных, устранения дублей и конфликтов.

Официальная [документация YouGile API v2](https://ru.yougile.com/api-v2#/) — источник актуальных методов. Перед массовыми действиями проверьте API, права и тариф своей компании. Установщик не создаёт удалённые объекты и не включает фоновую автоматизацию.
