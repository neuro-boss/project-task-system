Подключи этот репозиторий к системе задач TaskPlanner и YouGile, чтобы локальные задачи, их статусы, приоритеты и даты отражались на отдельной доске моего проекта. Работай с текущим репозиторием, моей компанией YouGile и моими правами; не используй чужие ID, задачи, категории или ключи.

Источник установки: https://github.com/neuro-boss/project-task-system
Инструкция по дополнительному подключению YouGile после установки TaskPlanner: https://github.com/neuro-boss/project-task-system/blob/main/references/yougile.md

Сначала прочитай README, SKILL.md и references/yougile.md из этого репозитория. Если навык ещё не установлен, помоги установить его через $skill-installer или используй опубликованный репозиторий как локальный источник. Не считай ссылку опубликованной до проверки её доступности. Для TaskPlanner используй проектный bootstrap только после сухого прогона; существующую доску не перезаписывай и не понижай её версию. Затем отдельно выполни dry-run `scripts/bootstrap_yougile.py`, проверь список изменений и только после этого примени установщик. Если в проекте уже есть интеграция YouGile, сравни реализации и не перезаписывай пользовательский код.

Перед работой прочитай AGENTS.md/другие правила проекта, .tasks/config.json (если есть), документацию и Git status. Если в проекте принят TaskPlanner, создай задачу на интеграцию, перемести её в In Progress и запиши короткий Plan до изменения кода. Сохраняй чужие незавершённые правки.

Настрой подключение под мой проект:

1. TaskPlanner `.tasks/*.md` остаётся главным источником. YouGile — одностороннее отображение. Задачи, которые клиент создал непосредственно в YouGile, не импортируй автоматически обратно; отдельно предложи безопасный будущий сценарий с правилами прав и разрешения конфликтов.
2. Используй отдельный YouGile-проект и доску для данного продукта либо явно выбранные мной существующие объекты. Рекомендуемые колонки слева направо: Бэклог → Следующие → В работе → Готово → Отклонено, соответствующие Backlog → Next → In Progress → Done → Rejected. Если API вставляет новые колонки слева, создавай их в обратном порядке и обязательно проверь фактический вид доски. Для повторения визуального стиля можно задать цветовые коды колонок 1, 3, 4, 6, 7 в этом порядке; цвет карточки по P0–P4 настраивается отдельно.
3. В `.tasks/yougile.local.json` запиши только локальные настройки: уникальный стабильный workspaceKey, ID выбранного проекта/доски/колонок, рабочий календарь, правила оценок и, при необходимости, продуктовые модули. Этот файл и локальные карты соответствий должны быть исключены из Git. В публичном примере не должно быть реальных ID или ключа.
4. API-ключ получи только для моей компании через её уполномоченного администратора. Не проси его значение в чат, не показывай его ни целиком, ни частично, не помещай в Git, JSON, команды или логи. Если у меня уже есть ключ для этой же компании, используй один защищённый файл вне репозиториев через `apiKeyFile` во всех моих проектах либо `YOUGILE_API_KEY`; не создавай ключ на каждый проект. Если файла нет, объясни, как мне самостоятельно безопасно создать/сохранить ключ, и дождись этого действия. Не отзывай и не перевыпускай общий ключ без отдельного запроса: это затронет все подключённые проекты.
5. Новая задача фиксирует `Created` и автоматическую оценку `Estimate`; при начале и завершении один раз фиксируются `Started` и `Completed`. `Due` ставит человек только как настоящий внешний срок. Прогноз для Next/In Progress рассчитывается из Estimate и рабочего календаря, не выдаётся за обещание. Backlog не получает плановые даты. Гант завершённой задачи показывает фактический интервал, если даты известны. Не подменяй серверную дату создания YouGile локальным полем Created: оно хранится как метаданные задачи/описание.
6. Изучи задачи проекта и предложи удобные взаимоисключающие «Модули» с примерным распределением и спорными совпадениями. Не копируй названия модулей чужого продукта. Создавай стикер только после моего утверждения списка. Если модули не нужны, оставь базовую синхронизацию без стикера.

Порядок проверки: локальный dry-run без сети → `--discover` → `--doctor` → пилот на одной реальной задаче → повторный пилот без дубля → проверка статуса, приоритета, дат и модуля в интерфейсе → массовая синхронизация активных задач → повторный запуск и сверка числа карточек/ID. Исторические Done импортируй отдельным режимом только после проверки подтверждаемых дат Git и WORK_LOG; не выдумывай даты. При сетевой ошибке сохраняй локальную задачу и карту соответствий, а затем повторяй идемпотентную синхронизацию, не создавая карточку вручную.

Установщик добавляет агентное правило точечной синхронизации после изменений TaskPlanner, но это не фоновый демон. Если нужен непрерывный мониторинг, сначала объясни вариант отдельного планировщика и его права/логи, не включай его молча. Соблюдай API rate limit (не менее 1250 мс между запросами по умолчанию). Не коммить, не публикуй, не делай production-деплой и не меняй удалённые объекты сверх явно согласованных доски/пилота без моего отдельного указания. В конце сообщи, что установлено, что проверено фактически, какие права/действия остались за мной и есть ли ограничения.
