# Общий YouGile для проектов

Схема: **инициализация проекта → подключение YouGile → отправка после правки задач → часовая подстраховка**.
`.tasks` остаётся источником истины. Никакой центральной базы задач или отдельного
постоянно работающего сервера нет. Общий локальный реестр объединяет подключения.

## Однократная настройка

Нужны Python 3.10+, Node.js 20+ и один проект с рабочими
`.tasks/yougile.local.json` и коннектором. Сначала настройте и проверьте его по
[инструкции одного проекта](yougile.md), если такого подключения ещё нет.
Выберите папки, где разрешено автоматически подключать будущие проекты, и
постоянную папку сервиса **за пределами установленного навыка**.

Команды выполняются из клона или установленной копии навыка. Замените все примеры
путей на свои; `existing-project` — разрешённый вами профиль той же компании:

```bash
python scripts/bootstrap_hub.py --hub-root /path/to/task-hub --root /path/to/projects --profile-from /path/to/projects/existing-project
python scripts/bootstrap_hub.py --hub-root /path/to/task-hub --root /path/to/projects --profile-from /path/to/projects/existing-project --apply
```

Первая команда — локальный просмотр без записи и API. Вторая устанавливает сервис,
выполняет **офлайн** поиск и включает hook навыка. Для нескольких папок повторите
`--root`. Сервис читает явно указанный `apiKeyFile` профиля; ключ не копируется и
не передаётся через чат/аргументы. `YOUGILE_API_KEY` здесь не используется, чтобы
случайно не выбрать другую компанию. Сам профиль и его файл ключа должны оставаться
доступными; хранить ключ лучше вне всех Git-репозиториев.

Для **Windows** добавьте `--schedule` к просмотру, затем к `--apply`:

```powershell
python scripts/bootstrap_hub.py --hub-root 'C:\TaskHub' --root 'C:\Projects' --profile-from 'C:\Projects\existing-project' --schedule
python scripts/bootstrap_hub.py --hub-root 'C:\TaskHub' --root 'C:\Projects' --profile-from 'C:\Projects\existing-project' --schedule --apply
```

Этот флаг явно разрешает скрытый запуск раз в час и первый запуск сразу после
установки. Первый запуск может принять существующие подключения и синхронизировать
активные задачи. Задача Windows получает имя `ProjectTaskHub-<идентификатор папки>`;
работает при включённом ПК и входе владельца в Windows, с ограниченными правами.
Точная версия Node сохраняется в локальном runtime.json. Системная ExecutionPolicy
не меняется. На **macOS/Linux** установите часовое выполнение через свой планировщик:

```bash
node /path/to/task-hub/cli.mjs tick --apply
```

Встроенная установка расписания пока поддерживает только Windows. Без расписания
подключение при bootstrap и ручная синхронизация работают; автоматического часового
повтора не будет. Установщик печатает план до применения; сетевые операции начинаются
при onboarding/tick, а не при офлайн-установке без `--schedule`.

## Как ведут себя проекты

- При успешном `bootstrap_project.py --apply` hook проверяет разрешённые реальные
  пути. Вне выбранных папок он ничего не регистрирует и не подключает.
- Внутри них существующая конфигурация принимается с прежними ID доски, колонок,
  workspaceKey и карты. При её отсутствии создаётся проект, доска и пять колонок;
  совпадающие объекты переиспользуются, неоднозначность останавливает подключение.
  Рабочий календарь, часовой пояс и оценки наследуются из выбранного профиля;
  категории, стикеры и ID другого продукта в новую доску не копируются. Перед
  созданием проверяется доступ ключа к исходному профилю.
- При установке сервиса уже существующие **ненастроенные** проекты становятся
  исключениями. Это не массовое создание досок для всех старых папок. Будущие
  проекты с `.tasks/config.json` подхватываются автоматически в пределах глубины поиска
  (по умолчанию четыре уровня). Пустые папки без `.tasks` не инициализируются фоном.
- После каждого изменения задачи агент запускает команду из управляемого блока
  правил. Это действие агента, а не наблюдение ОС за каждым сохранением файла.
- Раз в час выполняются поиск, повтор `onboarding.state=pending` и отправка пропущенных
  изменений. Недоступность API не отменяет создание проекта или локальную задачу.
  Конфликты пользовательских скриптов требуют разбора; файл не перезаписывается.
- Журнал настройки и стабильные ключи повторов сохраняют уже созданные удалённые ID.
  Карточки не удаляются. Старые Done/Rejected массово не импортируются. Поля клиента,
  назначения и посторонние стикеры сохраняются. Обратного импорта из YouGile нет.

Обычный preview и `--check` навыка не запускают сетевое подключение. Одно создание
папки или чата не вызывает hook: нужен bootstrap навыка либо последующее обнаружение
готовой `.tasks`-доски фоном.

## Проверка, пауза и обновление

Из папки установленного **сервиса**:

```bash
node cli.mjs status
node cli.mjs onboard --project /path/to/projects/new-project
node cli.mjs onboard --project /path/to/projects/new-project --apply
node cli.mjs audit --project /path/to/projects/existing-project
node cli.mjs sync --project /path/to/projects/existing-project --apply
node cli.mjs disable --project /path/to/projects/existing-project --apply
```

`onboard` без apply — без сети/записи. `audit` читает API и обновляет локальный кэш,
но не пишет в YouGile. `disable` сохраняет ручную паузу: часовой поиск не включает
проект обратно. Явный `adopt --project <путь> --apply` снимает паузу после проверки
существующего подключения. Для старого ненастроенного проекта из исключений используйте
явный сценарий `connect --profile-from <путь> --assets ./vendor/yougile`, затем мост
`python install-bridge.py --project <путь> --apply` и `adopt --apply`; сначала смотрите
preview каждой команды. Исключение можно оставить: явно подключённый проект уже enabled.

В `status` видны pending, ошибки и heartbeat; их сообщения не содержат приватных
ответов API. Неизменённый цикл обычно не вызывает API; раз в шесть часов выполняется
удалённая сверка. Между запросами общий лимит, ошибки 429/5xx учитываются при повторе.
Дубли через junction/worktree не создают второй источник: выбранный путь сохраняется.

Состояние — в `<hub>/.local/`, указатель hook — в
`$CODEX_HOME/project-task-hub.json`, по умолчанию `~/.codex/project-task-hub.json`.
Указатель хранит только пути Node/CLI/home. Не публикуйте его, настройки, карты,
ключи и резервные копии. Указатели в проектах исключены из Git; без них прежний
коннектор работает самостоятельно. Политика локальна: установка навыка другим
человеком не переносит вашу компанию или разрешения.

Обновление навыка из GitHub сохраняет внешний указатель и рабочий сервис. Чтобы
обновить сам runtime, остановите его расписание, повторите bootstrap_hub с теми же
путями (preview → apply), затем включите расписание. Изменённые вручную файлы
runtime сохраняются для разбора. Настройки/реестр и список исключений сохраняются;
резервные копии — `.local/backups/setup-*`. Другой существующий указатель не заменяется
без явного `--replace-pointer`.

## Запрос для Codex

```text
Используй $project-task-system и прочитай references/yougile-hub.md.
Настрой общий реестр и автоматическое подключение новых проектов в папке <моя папка>.
Сервис установи в <постоянная папка сервиса>, профиль моей компании возьми из
<мой уже подключённый проект>. Сохрани текущие доски, задачи и связи.
После инициализации проекта подключай YouGile сразу, после правки задач запускай
синхронизацию, а раз в час подхватывай пропущенные проекты и повторяй ошибки.
Сначала покажи локальный план без записи. Используй существующий защищённый файл
ключа, не запрашивай ключ в чат. На Windows установи часовой планировщик.
```


## Журнал и отчёты

Hub 0.3 поддерживает журнал значимых действий, отчёты day/week/month и локальный
экран обзора. Часовой tick обновляет latest-обзор без новых архивных копий; отчёт
по запросу создаёт снимок. Описания задач отправляются в безопасном HTML.
Подробнее — [activity-reports.md](activity-reports.md). Методы базы знаний пока
не включены: паспорт экспортируется локально из docs/project-passport.md.
